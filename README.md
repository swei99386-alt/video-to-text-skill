想看一段 YouTube / X / 哔哩哔哩视频讲了什么，但不想看完整段？或者想拿到一份能复制粘贴的文字稿？这个 Skill 让 AI 一句话帮你搞定。

它的策略很简单，但很关键：

> **永远先扒现成字幕，扒不到才动用听译。**

大多数正经视频（YouTube 演讲、播客）都自带字幕，几秒钟就能扒下来免费拿到稿子。只有在确实没字幕时，才下载视频、用显卡跑听译。这条铁律能省掉你下整段视频 + 听半小时的死功夫。

## 你能得到什么

![演示图占位](https://via.placeholder.com/800x400.png?text=Showcase+Image+Here)
*(建议后续将此处替换为实际运行截图)*

- **一段视频链接或本地文件** → 拿到一份**干净纯文字稿**，直接 `完整文字稿.txt`。
- 支持 **X / Twitter**、**YouTube**、**哔哩哔哩** 和本地音视频文件。
- 没字幕的视频自动用显卡听译（速度比 CPU 快 18 倍）。
- 5G 老显卡也能扛 **4 小时 35 分以内的视频不爆显存**（实测通过）。
- 支持中文（自动简体）、英文、及其他主流语言。
- 可选 `--visual` 模式：额外生成关键帧、画面 OCR 和时间线证据，帮助后续多模态模型核对画面。

视觉模式是“先取证”，不是直接把整段视频上传给云端模型。它默认在本机运行，输出可回看的图片和结构化 JSON；需要更高层的画面总结时，再把证据包交给 Gemini 等多模态模型。

## 适合谁

**只想转文字的人**：把链接交给 Claude Code 或其他能跑命令的 AI，一句话出结果。

**会用 Claude Code / Codex 等 AI 编程工具的人**：把这个 Skill 装上，以后遇到"扒这个视频的话"这类需求时，AI 自己知道怎么走。

## 三步上手

### 1. 装好依赖

```bash
# 必需：视频下载 + 字幕
pip install yt-dlp ffmpeg

# 听译需要（仅当没字幕时才走）
pip install faster-whisper torch

# 视觉证据模式需要（仅当使用 --visual 时）
# 安装 Node.js 18+，使 npx 可用；视觉分析包由 npx 临时放入 npm 缓存
```

### 2. 给 AI 一句话

```text
帮我把这段视频的话转成文字稿：https://www.youtube.com/watch?v=xxxxxx
```

或者直接装成 Skill，让 AI 看到链接就自动转。

如果 Skill 安装在其他智能体目录，把 `<SKILL_DIR>` 替换为当前 `SKILL.md` 所在目录：

```bash
python "<SKILL_DIR>/scripts/grab.py" "<视频链接或本地视频>" "输出文件夹名" [语言] --visual
```

### 3. 看桌面上的输出

跑完会自动在桌面建一个文件夹，里面有：

| 文件 | 干啥用的 |
|------|---------|
| `完整文字稿.txt` | 你要的最终成品，纯文字 |
| `audio.srt` | 带时间戳的字幕版（万一要核对"原话是几分几秒说的"） |
| `media.mp4` / `audio.wav` | 中间产物，看完稿可删 |
| `视频理解报告.md` | 画面证据、OCR 和时间线的可读报告（仅视觉模式） |
| `视觉证据.json` | 可供后续模型读取的结构化证据（仅视觉模式） |
| `关键帧/` | 可按时间回看的画面图片（仅视觉模式） |

## 可选视觉证据模式

只有明确需要画面信息时才加 `--visual`。它会在现有字幕/听译流程之后，分析本地视频或可下载的视频链接：按场景变化抽帧、固定间隔补采、去掉相似画面，并尝试 OCR。每条证据都带时间戳和关键帧路径。

当前视觉层提供关键帧、OCR 和时间线，不会凭文字稿臆造画面内容，也不会默认调用云端多模态 API。要做“这页 PPT 的真正含义是什么”这类深层理解，可以把 `视觉证据.json`、文字稿和关键帧交给另一个多模态模型。

## 它不会做什么

- **不翻译**——只转写视频里说的话，英文听出来就是英文，中文就是中文。要翻译请自己用 AI。
- **不下载整个视频当默认**——除非没有字幕才下。这是核心策略。
- **不保证 100% 准确**——听译是"听个大概"，碰到多人抢话、严重口音、嘈杂背景音乐会差一些。
- **不处理加密 / 登录限定视频**——微信视频号、会员专享这类，工具链够不着。
- **视觉模式不是完整的视频大模型**——它先生成可核对的画面证据；复杂画面理解要交给多模态模型，OCR 也可能受分辨率、字体和语言包影响。

## 性能数据（2026-08 实测）

| 视频时长 | 听译耗时 | 显卡表现 |
|---------|---------|---------|
| 10 秒静音 | 0.5 秒 | 没问题 |
| 2 小时 17 分（英文工作坊） | **7 分 23 秒** | 5G 显卡不爆 |
| 4 小时 35 分（拼接测试） | **15 分 18 秒** | 5G 显卡不爆（不切段） |

**听译速度 ≈ 18 倍实时**——翻译机听 1 小时音频只花 3 分钟。

## 核心策略：为什么"先扒字幕"？

曾经有过一次踩坑：明明 YouTube 上有现成字幕，硬是把 450MB 视频下下来用处理器（CPU）硬跑半小时听译，结果还跑出一堆错字。

从那以后这条铁律就写死：
1. **永远先** `yt-dlp --write-subs --write-auto-subs` 扒字幕
2. 扒到 → 秒出文字稿，收工
3. 扒不到 → 才下载媒体 → 抠声音 → 显卡跑听译

这条铁律让"90% 的视频"几乎**零成本**出稿。

## 调参小贴士

`scripts/grab.py` 里的常量 `SEGMENT_SECONDS` 控制什么时候启用切段（>4 小时 35 分才切）。改这个数字就能调阈值。

- **想要更激进**（少切）：调大，比如 `999999`
- **想要更保守**（多切）：调小，比如 `1800`（30 分钟）
